# MVP Scope

## Prototype Direction

The first MVP is a lean interview prototype, not a full SaaS dashboard.

The user starts with a conversation, not a complex setup form.

## Must Have

- Ukrainian and English language support
- email-based session start
- simulated email code verification
- previous session lookup by email
- owner link/admin view
- project creation
- conversational project type discovery
- text-based AI interview
- interview history storage
- working context Markdown
- short brief generation
- Client Brief generation
- clarity map
- Brief Maturity Score
- brief readiness criteria
- contradiction list
- Markdown export
- unfinished session recovery
- raw brief generation from incomplete sessions
- owner-reviewed incomplete-session follow-up draft

## Deferred From First Prototype

- full registration
- login
- dashboard
- separate full document suite
- advanced PDF branding
- payments

## Language Requirements

- MVP supports Ukrainian and English.
- Interviewer responds in the user's language.
- Russian may be handled by auto-detection in interview, but official document languages are Ukrainian and English.
- Generated documents should be produced in the client's language where possible, with Ukrainian and English as primary supported outputs.
- Client-specific phrases should be preserved even when the final document language differs.

## Version 2

- voice interview
- image and reference upload
- white label for agencies
- team access
- interview templates
- Notion and Google Docs integrations
- public client links
- contractor comments
- client brief approval
- change history
- payments
- API

## MVP Success Signal

The MVP should show whether users perceive the generated brief as clearer and more useful than a traditional intake form.
